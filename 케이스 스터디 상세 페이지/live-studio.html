Case study ・Healthcare Monitoring

제각각이던 심전도 모니터링 디자인을, 개발자와 실시간으로 공유되는 하나의 시스템으로 통일하다.

SHIPPED 2024.02.01 - 2025.01.01・11개월 UI/UX Designer MEZOO・Healthcare Figma
Background Problem Approach Workflow Outcome Learned Result
Background
MEZOO의 심전도 모니터링 사이트, Live Studio. 판독자와 환자의 상태를 실시간으로 보여주는 서비스다.
Problem
디자인 시스템이 통일돼 있지 않아 내부 작업자 간 소통 문제가 잦았다. 다양한 알림 UI를 계속 늘려가야 하는 서비스 특성상 문제는 점점 커지고 있었다.
Approach
공식적으로 공유 가능한 디자인 파일을 만들고, 디자인이 바뀔 때마다 개발자에게 실시간으로 알림이 가도록 프로세스를 정비.
Outcome
디자인 파일을 훨씬 빠르고 정확하게 업데이트·공유할 수 있게 됐고, 작업자 간 확인 과정도 명확해졌다.

Background

같은 화면인데, 팀마다 조금씩 다르게 그려지고 있었다.

Live Studio는 하이카디(심전도 측정 기기)로 측정한 데이터를 실시간으로 모니터링하는 사이트다. 환자 상태를 다양한 알림으로 보여줘야 하는 서비스 특성상, 화면과 컴포넌트의 수는 계속 늘어나고 있었다.

디자인 시스템이 공식적으로 정리돼 있지 않다 보니, 같은 컴포넌트도 화면마다 조금씩 다르게 구현되고 있었다.

Problem

디자인 시스템의 부재는, 결국 소통의 문제였다.

디자이너와 개발자가 서로 다른 버전의 컴포넌트를 보고 작업하는 일이 반복됐다. 공식 기준이 없다 보니 "어떤 게 맞는 디자인인지" 확인하는 데만 불필요한 시간이 들었다.

Observation #1 / Observation #2

알림 컬러가 화면마다 조금씩 달라, 같은 상태를 나타내는지조차 헷갈리는 경우가 있었다.

디자인이 수정돼도 개발자에게 실시간으로 전달되지 않아, 예전 버전으로 개발이 진행되는 일이 있었다.

Approach

공식적으로 공유되는, 단 하나의 파일.

모든 컴포넌트와 알림 컬러를 정리한 공식 디자인 파일을 만들고, 이 파일을 기준으로 개발자와 실시간 공유하는 체계를 만들었다.

알림 컬러 체계를 상태별로 공식 지정
아이콘·컴포넌트 스타일 통일
디자인 변경 시 개발자에게 실시간 알림
변경 사항을 확인·인지할 수 있는 공유 프로세스 구축
공식 컬러 기준 없이 기능 추가 시마다 임의 지정 디자이너-개발자 간 최신 버전 불일치 알림 종류가 늘수록 일관성 저하
Workflow

디자인 변경이, 곧바로 개발 알림으로.

디자인을 수정하면 공유 파일에 반영되고, 이 변경 사항이 실시간으로 개발자에게 알림으로 전달되는 흐름을 만들었다. 확인과 인지, 반영까지 이어지는 루프를 짧게 만드는 게 목표였다.

Outcome

흩어져 있던 기준이, 하나의 시스템으로.

파일 업데이트·공유 속도
훨씬 빠르고 정확하게 개선
디자인 변경 알림
개발자와 즉시 확인·인지 기능
사용자 UI 개선
기존 대비 심전도 화면 가독성 향상
Learned

디자인 시스템은 화면이 아니라, 공유 프로세스다.

처음엔 컴포넌트를 정리하는 작업이라고 생각했다. 하지만 진짜 문제는 정리된 결과물을 어떻게 "계속 최신 상태로" 유지하고 공유하느냐였다.

한 번 만들고 끝나는 파일이 아니라, 변경이 생길 때마다 관련된 사람에게 자연스럽게 전달되는 흐름을 만든 것이 이 프로젝트의 핵심이었다.

Result

이제는 하나의 기준으로 말하는 팀.

디자이너와 개발자가 같은 파일, 같은 컬러 기준을 보고 이야기하게 되면서 화면을 둘러싼 불필요한 확인 작업이 크게 줄었다.
